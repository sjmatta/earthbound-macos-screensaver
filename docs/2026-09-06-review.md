[Aerial source](https://github.com/AerialScreensaver/Aerial), [release information](https://aerialscreensaver.github.io/)

Its technical notes describe per-extension process isolation and private screensaver classes. Prototype this host with the current renderer first, testing whether WKWebView behaves correctly under its sandbox and lifecycle. [Sample](https://github.com/AerialScreensaver/AppexSaverMinimal), [technical background](https://github.com/AerialScreensaver/AppexSaverMinimal/blob/main/BACKGROUND.md)

## Fidelity priorities

These findings come from `src/main.js`, `src/index.html`, and the installed pinned engine under `node_modules/earthbound-battle-backgrounds/src/`.

| Priority | Finding | Recommended update and acceptance evidence |
| --- | --- | --- |
| 1 | The engine selects only `e2 || e1` from the distortion entries. `distorter.js` explicitly describes sequencing as unfinished. Movement fields are not used to scroll the image. | Implement ROM-defined distortion durations/sequences and scrolling tables. Verify transitions and accumulated offsets against known game captures, including long sessions. |
| 1 | The wrapper advances one tick per rendered frame at a nominal 30 FPS. Palette cycles also mutate on every render, and the engine divides palette duration by two. New layers begin with fresh palettes but inherit a session-global distortion tick. | Separate simulation advancement from drawing; give each background an explicit start time. Establish the game's timing from reference captures before changing FPS. Rendering at 30, 60, or 120 Hz must produce the same state at a given simulation time. Merely setting FPS to 60 would change behavior. |
| 1 | Random pairs and fixed half-opacity are artistic choices, not evidence of original battle compositions. | Add an authentic mode with source-backed encounter/pair metadata, appropriate single-layer behavior, and validated SNES color math, transparency, rounding, and palette conversion. Keep unrestricted pairing in remix mode. |
| 2 | A 256×224 canvas stretches independently to the screen's width and height. | Offer explicit source-pixel, 4:3 display, and fill modes. Use nearest-neighbor scaling and make cropping/stretching an intentional choice. |
| 2 | Crossfades mix four layers through an 8-bit destination, so each contribution can be rounded before the next is added. | In remix mode, blend completed pair images once for predictable transitions. Authentic mode can cut between scenes. Compare color values rather than assuming weights summing to one guarantees identical quantization. |
| 2 | No frame-reference suite proves the renderer matches the game. | Add deterministic capture at chosen scene/tick values, raw-pixel comparison with a reference emulator, and temporal checks across palette and distortion boundaries. Include horizontal, interlaced, vertical, scrolling, single-layer, and special scenes. Record reference ROM/version and capture conditions. |
| 3 | Layer labels currently fall back to indices and distortion types because `layerNames.json` is empty. | Populate verified encounter names and add favorites/exclusions, thumbnails, shuffle without immediate repeats, and an option to hide overlays. Label invented pairings as remixes. |

CoilSnake's battle-background documentation, edited July 15, 2026, describes separate scrolling and distortion tables and frame-based palette cycling. Use it to resolve the upstream engine's TODOs, rather than treating old field names as authoritative. Its documented color-depth constraints also support separating authentic compositions from arbitrary pairs. [CoilSnake battle-background documentation](https://github.com/pk-hack/CoilSnake/wiki/Battle-Backgrounds)

## Host and renderer direction

Recommended sequence:

1. Create a deterministic renderer interface and a small reference corpus. Fix scrolling, effect sequencing, and timing against that corpus.
2. Build an app with a normal preview window and an experimental `.appex` target around the same renderer. Retain the existing `.saver` while evaluating OS compatibility and distribution.
3. Measure CPU, GPU, memory, startup, and post-dismissal activity. Consider a Swift core with Metal presentation if it materially reduces power or removes persistent WebKit failures. A Metal port is a rendering backend change; it cannot supply missing emulation semantics by itself.
4. Before release, test actual activation, settings previews, rapid unlock/relock, repeated stop notifications, display attach/detach, and multiple monitors. The current per-view delayed `exit(0)` and private occlusion selector need explicit coverage. Repeated stop notifications can overwrite `pendingExit` while older work remains scheduled; restarting only cancels the most recently stored work item.
5. Add Developer ID signing/notarization for distribution and explicit OS/architecture build coverage. Ad-hoc signing checks are useful locally but do not validate user installation through Gatekeeper.

Do not call the current implementation cycle-accurate. It is a ROM-derived visualizer with useful existing rendering and lifecycle improvements; accuracy should become a measured property.

## Validation scope

The refresh builds with Node 24.13.0 and Xcode 26.6 on macOS 26.5.2. The full `task build` succeeded, including `npm ci` and the existing file-URL output checks. npm reported zero known vulnerabilities. Host activation and visual agreement with an emulator require separate runtime validation; a successful build does not establish either.

The resulting bundle contains both `x86_64` and `arm64`; strict code-signature verification passed, and its bundled JavaScript matches the web build. A Node VM smoke check with mocked DOM/Canvas rendered three opaque frames for each of the 327 layer IDs and verified loop cancellation. This is execution coverage, not browser or reference-image validation.
